# עורך וידאו — Video Editor

כלי ווב אישי להכנת סרטוני שיווק לאפליקציות: חיתוך סרטונים, הוספת סגיר (outro),
ויצירה אוטומטית של כיתוב (caption) שיווקי באנגלית באמצעות Claude API.

## מה המערכת עושה

1. **אפליקציות (נכסים)** — מנהלים רשימת אפליקציות. לכל אפליקציה: שם, תיאור/אופי,
   לינק שיווקי, האשטאגים, וספריית סגירים משלה.
2. **עיבוד חדש** — בונים באצ' של בקשות. לכל בקשה: סרטון מקור (העלאת קובץ או
   לינק — כולל יוטיוב/טיקטוק דרך yt-dlp), שניית חיתוך, אפליקציה וסגיר.
   לחיצה אחת על "שלח לעיבוד" מריצה את כל הבאצ' ברקע.
3. **העיבוד** — הסרטון נשמר מההתחלה ועד שניית החיתוך, הסגיר מנורמל
   (רזולוציה/קצב פריימים/אודיו) ומשורשר מיד אחריו. מהקטע החתוך נשלפים פריימים
   שנשלחים ל-Claude יחד עם פרטי האפליקציה, ו-Claude מחזיר כיתוב שיווקי באנגלית
   עם hook לפי תוכן הסרטון, קריאה להורדה, הלינק וההאשטאגים.
4. **תוצאות** — סטטוס חי לכל בקשה, נגן וידאו, הורדת ה-mp4 והעתקת הכיתוב.
   התוצרים נשמרים גם אחרי הפעלה מחדש.

## גישה מרחוק — הכל בתוך GitHub, בחינם

המערכת רצה כולה על התשתית של GitHub, בלי אף ספק חיצוני:

- **הממשק** מתארח ב-GitHub Pages:‏ `https://dudimaman.github.io/video-editor/`
- **העיבוד** (ffmpeg + Claude) רץ ב-GitHub Actions — חינם ללא הגבלה בריפו ציבורי
- **התוצרים** נשמרים כ-Releases של הריפו, עם לינקים ישירים להורדה

### הפעלה ראשונית (פעם אחת)

1. **מפתח API**: בריפו — Settings → Secrets and variables → Actions →
   New repository secret → שם: `ANTHROPIC_API_KEY`, ערך: המפתח שלך.
   (בלעדיו יופקו כיתובי דמה.)
2. **הפעלת האתר**: Settings → Pages → תחת "Build and deployment" לבחור
   Source: **Deploy from a branch**, ואז Branch: **gh-pages** ותיקייה
   `/ (root)` → Save. תוך דקה-שתיים האתר יעלה לכתובת למעלה.
   (ה-branch‏ gh-pages כבר קיים — ה-workflow מעדכן אותו בכל שינוי.)
3. **טוקן אישי** (נדרש רק לשליחת סרטונים וניהול אפליקציות מהממשק —
   צפייה בתוצאות פתוחה בלי כלום): בכניסה הראשונה לאתר ייפתח מסך
   "חיבור ל-GitHub" עם הוראות — יוצרים
   [Fine-grained token](https://github.com/settings/personal-access-tokens/new)
   מוגבל לריפו הזה עם הרשאות Read/Write ל-**Contents** ול-**Actions**,
   ומדביקים אותו שם. הטוקן נשמר רק בדפדפן שלך.

### איך זה עובד

שליחת באצ' מהממשק מפעילה את ה-workflow‏ `process-videos`, שמוריד/קורא את
הסרטונים, חותך, משרשר סגיר, יוצר כיתוב מול Claude, ומפרסם Release בשם
`batch-N` עם קבצי ה-mp4 והכיתובים. טאב "תוצאות" קורא את ה-Releases ומציג
הכל.

שתי דרכים נוספות לשלוח באצ' בלי הממשק (ובלי טוקן):
- **עריכת `queue.json`** ישירות באתר GitHub — כל שינוי בקובץ על main מפעיל
  עיבוד של הבקשות שבו (קובץ ריק `[]` לא עושה כלום).
- Actions → process-videos → **Run workflow**, עם JSON של בקשות.

### כדאי לדעת

- הריפו ציבורי ⇒ גם התוצרים (Releases) והסרטונים שמעלים דרך הממשק
  (נשמרים בתיקיית `inbox/` בריפו) ציבוריים. לסרטוני שיווק זה בדרך כלל
  בסדר גמור; למקורות רגישים עדיף לינק במקום העלאת קובץ.
- קבצים שהועלו ל-`inbox/` נשארים בהיסטוריית הריפו; אפשר למחוק אותם
  מדי פעם כדי לשמור על ריפו רזה.

## הרצה מקומית (אופציונלי)

אפשר להריץ את אותה מערכת גם על המחשב שלך עם שרת מקומי מלא (טאב תוצאות
מתעדכן בזמן אמת, בלי צורך בטוקן):

## דרישות מוקדמות

- Python 3.11+
- Node.js 18+
- **ffmpeg + ffprobe** זמינים ב-PATH:
  - Ubuntu/Debian: `sudo apt-get install -y ffmpeg`
  - macOS: `brew install ffmpeg`
- מפתח Anthropic API (אופציונלי — בלעדיו המערכת מייצרת כיתוב mock לבדיקות)

## התקנה

```bash
cp .env.example .env        # ערכו והכניסו ANTHROPIC_API_KEY

cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

cd ../frontend
npm install
```

## הרצה (פיתוח — שני טרמינלים)

```bash
# טרמינל 1 — backend
cd backend && . .venv/bin/activate
uvicorn app.main:app --reload --port 8000

# טרמינל 2 — frontend
cd frontend
npm run dev                 # http://localhost:5173 (מפנה /api ל-8000)
```

אפשר גם להריץ הכל משרת אחד: `cd frontend && npm run build` ואז ה-backend
יגיש את ה-UI ישירות מ-http://localhost:8000.

## משתני סביבה (`.env`)

| משתנה | ברירת מחדל | תיאור |
|---|---|---|
| `ANTHROPIC_API_KEY` | (ריק) | מפתח ה-API. ריק ⇒ כיתובי mock |
| `CLAUDE_MODEL` | `claude-sonnet-5` | המודל ליצירת כיתובים |
| `DATA_DIR` | `./data` | מיקום הקבצים וה-DB |
| `FFMPEG_WORKERS` | `2` | מספר סרטונים שמעובדים במקביל |
| `CAPTION_MOCK` | (ריק) | `1` ⇒ כיתובי mock גם עם מפתח |

## אחסון

הכל תחת `data/` (לא נכנס ל-git, בטוח לגבות או למחוק לאיפוס מלא):

```
data/app.db                    # SQLite — נכסים, סגירים, באצ'ים ובקשות
data/uploads/{request_id}/     # סרטוני מקור (העלאות והורדות)
data/outros/{asset_id}/        # קבצי הסגירים
data/outputs/{request_id}/     # final.mp4 — התוצרים המוכנים
data/frames/{request_id}/      # פריימים שנשלחו ל-Claude
```

## הערות

- כלי אישי לשימוש מקומי — אין אימות משתמשים; לא לחשוף לאינטרנט כמו שהוא.
- מקורות נתמכים: העלאת קובץ, לינק ישיר לקובץ וידאו, וכל אתר ש-yt-dlp תומך בו.
- כישלון של סרטון אחד בבאצ' לא עוצר את השאר; אם רק יצירת הכיתוב נכשלה,
  הווידאו נשמר ואפשר ללחוץ "צור כיתוב מחדש" מטאב התוצאות.
